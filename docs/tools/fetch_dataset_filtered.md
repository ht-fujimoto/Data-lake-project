# fetch_dataset_filtered ツール詳細設計書

## 概要
フィルタ条件を指定してE-statデータセットを取得するツール。地域、時間軸、分類などの条件でデータを絞り込んで取得します。

## 目的
- 必要なデータのみを効率的に取得
- データ転送量の削減
- 特定条件のデータ分析

## 入力パラメータ

### 必須パラメータ
- `dataset_id` (string): データセットID
- `filters` (object): フィルタ条件
  - キー: フィルタ項目名
  - 値: フィルタ値

### オプションパラメータ
- `save_to_s3` (boolean): S3保存フラグ
  - デフォルト: true

## フィルタ条件

### サポートされるフィルタ
| フィルタキー | E-stat APIパラメータ | 説明 | 例 |
|------------|-------------------|------|-----|
| `area` | `cdArea` | 地域コード | "13000"（東京都） |
| `time` | `cdTime` | 時間軸コード | "2020"（2020年） |
| `cat01` | `cdCat01` | 分類1 | "001"（男性） |
| `cat02` | `cdCat02` | 分類2 | "002"（女性） |
| `cat03` | `cdCat03` | 分類3 | "003"（総数） |

### カスタムフィルタ
- その他のフィルタは`cd{Key}`形式に自動変換
- 例: `{"custom": "value"}` → `cdCustom=value`

## 出力形式

### 成功時
```json
{
  "success": true,
  "dataset_id": "データセットID",
  "filters": {フィルタ条件},
  "record_count": レコード数,
  "s3_path": "s3://bucket/key",
  "sample": [サンプルレコード（最大3件）],
  "message": "メッセージ"
}
```

### 失敗時
```json
{
  "success": false,
  "error": "エラー詳細",
  "message": "エラーメッセージ"
}
```

## 処理フロー

1. **環境変数の取得**
   - `ESTAT_APP_ID`: APIキー
   - `AWS_REGION`: AWSリージョン
   - `DATALAKE_S3_BUCKET`: S3バケット名

2. **フィルタパラメータの変換**
   - フィルタオブジェクトをE-stat APIパラメータに変換
   - 標準フィルタは定義済みマッピングを使用
   - カスタムフィルタは自動変換

3. **API呼び出し**
   - エンドポイント: `getStatsData`
   - 基本パラメータ + フィルタパラメータ
   - タイムアウト: 60秒

4. **データ解析**
   - `VALUE`配列を抽出
   - レコード数をカウント

5. **S3保存**
   - パス形式: `raw/{dataset_id}/{dataset_id}_{filter_str}_{timestamp}.json`
   - フィルタ文字列: `key1_value1_key2_value2`形式

## 使用例

### 地域フィルタ
```python
{
  "dataset_id": "0003410379",
  "filters": {
    "area": "13000"  # 東京都のみ
  }
}
```

### 複合フィルタ
```python
{
  "dataset_id": "0003410379",
  "filters": {
    "area": "13000",  # 東京都
    "time": "2020"    # 2020年
  }
}
```

### 分類フィルタ
```python
{
  "dataset_id": "0003410379",
  "filters": {
    "area": "13000",
    "cat01": "001",   # 男性
    "time": "2020"
  }
}
```

## フィルタ値の確認方法

1. **メタデータAPIの使用**
   - `getMetaInfo`エンドポイントで利用可能なコードを確認

2. **サンプルデータの確認**
   - フィルタなしで少量取得し、コード値を確認

3. **E-stat公式ドキュメント**
   - 統計表ごとのコード定義を参照

## エラーハンドリング

### エラーケース
1. **無効なフィルタ値**
   - 存在しないコード値
   - 結果: 空のデータセット

2. **フィルタ組み合わせエラー**
   - 矛盾する条件
   - 結果: 空のデータセット

3. **APIエラー**
   - 不正なパラメータ形式
   - 対処: フィルタ条件を確認

## パフォーマンス考慮事項

### 利点
- **データ転送量削減**: 必要なデータのみ取得
- **処理時間短縮**: レコード数が少ない
- **コスト削減**: S3ストレージとAPI呼び出し削減

### 推奨使用シーン
- 特定地域のデータ分析
- 特定年度のデータ取得
- 分類別の集計

## 制限事項

- **最大レコード数**: 100,000件（フィルタ後）
- **フィルタ数**: E-stat APIの制限に従う
- **AND条件のみ**: OR条件は未サポート

## セキュリティ考慮事項

- APIキーの環境変数管理
- S3アクセスのIAMロール使用
- フィルタ値のサニタイゼーション（URL安全）

## 依存関係

- `requests`: HTTP通信
- `boto3`: S3操作
- `json`: データ解析
- `datetime`: タイムスタンプ生成

## 関連ツール

- `fetch_dataset`: フィルタなし取得
- `fetch_dataset_auto`: サイズ自動判定
- `search_estat_data`: データセット検索

## ベストプラクティス

1. **段階的なフィルタリング**
   - まず少量のデータで確認
   - フィルタ値を確認してから本番取得

2. **フィルタの組み合わせ**
   - 必要最小限のデータに絞る
   - 複数フィルタで精度向上

3. **エラーハンドリング**
   - 空の結果を想定
   - フィルタ値の妥当性確認
