## 技術的な発見と学び

### 1. Icebergテーブル作成の正しい方法

**問題**: 単純なGlue Data Catalogへの登録では、Icebergメタデータが不足してAthenaでクエリできない

**解決策**: Athena経由で`CREATE TABLE ... WITH (table_type='ICEBERG')`を使用

**理由**:
- Icebergテーブルには`metadata.json`、マニフェストファイルなどが必要
- Athenaが自動的にこれらのファイルを生成
- Glue Data Catalogへの登録も自動的に行われる

### 2. スキーマ推論の簡易実装

**アプローチ**: サンプルデータから型を推定

**利点**:
- 実装がシンプル
- 追加の依存関係不要
- 小規模データセットには十分

**制限**:
- 複雑な型（ネストされた構造など）には対応していない
- サンプルデータに依存するため、データの多様性が重要

### 3. データセット単位テーブルの有効性

**メリット**:
- 各データセットが独立したスキーマを持てる
- スキーマ変更の影響範囲が限定的
- データセット単位での管理が容易

**デメリット**:
- テーブル数が多くなる（100データセット = 100テーブル）
- クロスデータセットのクエリが複雑
